# API Key 类型设计

## 先看别人怎么做

设计之前查了三类来源：

1. **1Password** 有独立的 `API Credential` 条目类别
   （[item categories](https://www.1password.dev/cli/item-fields)），
   与 Login / Credit Card 平级，不是「自定义字段凑出来的」。
2. **AWS Secrets Manager** 的建议是把每把 key 存成**结构化 JSON**，
   能按字段单独读取与轮换。换句话说，**一段不透明的字符串是存不全的**。
3. 社区提案里反复出现的字段是：service name、**environment**、
   expiration、**rotation schedule**、**scope**
   （[1Password 社区](https://www.1password.community/developers-69/new-item-type-recommendation-api-keys-23306)）。

## 第一版错在哪

我最初的字段是：

```
服务商 / API Key / Base URL / 组织·项目 / 额度·计费 / 到期时间
```

对着上面三条一比，缺了三样最要紧的：

| 缺什么 | 后果 |
| --- | --- |
| **Key ID** | AWS / 阿里云这类是「ID + Secret」两段式，只有一个 Secret 等于存不全，用户只能拿备注补 |
| **环境** | 同一服务在 dev / prod 各有一把 key 是常态。没有这个字段，两条记录长得一模一样，只能靠标题写 `(prod)`，迟早出事故 |
| **权限范围 / scope** | 决定泄露后的影响面。不写下来，出事时不知道该慌到什么程度 |

反而多放了一条 **「额度 / 计费」**——那是账单信息，不是凭据属性，
而且会过期、会变，写在密码管理器里很快就会和真实情况不符。

## 现在的字段

| 字段 | 打码 | 提示语 | 为什么 |
| --- | --- | --- | --- |
| 服务商 | 否 | `OpenAI / Anthropic / AWS / 自建…` | 用来筛与搜 |
| **环境** | 否 | `prod / staging / dev` | 一等字段才能按它筛 |
| **Key ID** | 否 | `AKIA… 这类公开标识，没有就留空` | 两段式凭据的前半段 |
| **Secret** | **是** | `sk-… / 访问密钥，粘贴进来` | 核心秘密 |
| **权限范围** | 否 | `只读 / 读写 / 具体 scope` | 决定泄露影响面 |
| Base URL | 否 | `走代理或自建时填，官方留空` | 自建/代理端点 |
| 到期时间 | 否 | `YYYY-MM-DD，不过期就留空` | 很多 key 不过期，可留空 |
| 轮换周期 | 否 | `例如 90 天` | 比「到期」更实用的运维纪律 |

Key ID 不打码是刻意的：它会出现在请求头与日志里，**根本不是秘密**，
打码只会让人没法核对。全部字段里只有 Secret 是秘密。

## 为什么用自定义字段而不是复用 `password`

`password` 会参与「弱密码」「重复使用」两项安全统计。
一个 50 位十六进制的 API Key 在那两个统计里毫无意义
（必然被判强，也不该报重复使用）。语义不对的复用会污染安全视图。

## 提示语为什么要存在

「环境」「权限范围」这类字段光有标签不够——用户不知道该填
`prod` 还是「生产环境」，也不知道 scope 要不要写全。
一句示例比一整段说明更容易被读完。

为此给 `FieldTemplate` 加了 `hint` 字段，`serde(default)`：
老库里的模板没有它，读进来是空串，编辑框就不显示提示。
**纯增量，不需要数据迁移。**

## 打码字段必须能临时看一眼

原来字段一旦勾了「隐藏」就**永远打码**，用户粘贴完 Secret 没法确认
粘全了没有，只能存进去再到别处试——那意味着「先失败一次才知道对不对」。
现在每行有一个眼睛按钮临时切换明文，状态只存在对话框里，
**不写进库里**（一个「我默认显示明文」的开关留在库中，下次别人也能看到）。

## 迁移：老库怎么看到这个类型

类型表存在 `vault.dat` 里，加了新内置类型后已有的库不会自动出现它。
补在 `VaultData::migrate_legacy()`：只补 `APIKEY` 这一个。

不碰其它内置类型：用户可能主动删了「笔记」，每次打开都加回去会很烦；
而 API Key 是本版新增的，老库里不可能「被用户删过」。

## 已知限制

- **不做格式校验**。`sk-` 开头的未必是 OpenAI，`AKIA` 开头的未必是 AWS，
  各家格式还在变。校验错了会挡住合法输入，比不校验更糟。
- **不做轮换提醒**。「轮换周期」目前只是记录，没有到期弹窗。
- **没有预设服务商模板**。选了「AWS」不会自动把字段名换成
  `Access Key ID` / `Secret Access Key`。字段名是通用的。
- **不给「环境」做下拉**。`prod` / `staging` / `dev` 只是提示语里举例，
  实际写法各团队不同（有人用 `production`、有人用 `prd`）。
  做成自由文本 + 提示，比强制枚举更实用。
