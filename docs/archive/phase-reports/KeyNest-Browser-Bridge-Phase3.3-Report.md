## 1. 为什么选阅读模式当 B 类第一个

它压到的是骨架里**唯一还没被真实调用过**的能力：`scripting`。

`scripting` 从阶段 2.8 就声明在 manifest 里，但代码里**一次都没用过**。
权限清单只能比对"模块声明 vs manifest"，查不出"声明了但没代码用"这种
逆向的权限膨胀。只有一条真实用例能把它压出来。

顺带压到的还有一条从未验证过的链路：**host 权限是按站点申请的**，
不是安装时一次性授予。

## 2. 核心设计：宁可少提，不可提错

阅读模式最坏的失败不是"不好看"，是**把页面弄坏**。所以整条设计围绕一件事：
**提不出正文时什么都不做。**

### 2.1 三条不变式

| # | 不变式 | 为什么 |
| --- | --- | --- |
| 1 | **绝不移动原始节点，只克隆** | 退出时只需移除克隆出的容器，页面必定回到原样。移动节点后要还原的东西太多（事件监听、iframe、canvas 全都会坏） |
| 2 | **提不出正文返回 `NO_CONTENT` 且不留痕迹** | 显示一页空白比不做功能糟糕得多 |
| 3 | **所有 CSS 选择器都以阅读模式 class 或内容 id 开头** | 否则可能误伤正文内部的表格、列表、代码块 |

第 3 条有测试守着（`reader-core.test.js` 的「所有选择器都以阅读模式 class 开头」）：
它把 CSS 按规则切开，逐条检查选择器前缀。

### 2.2 正文提取的启发式

```text
1. 语义标签优先：article / main / [role=main] / [itemprop=articleBody]
   —— 但要求文本 >= 200 字，否则可能只是包了个标题
2. 否则按文本密度打分：
     sqrt(正文字数) * 2 + 标点数 * 5 - 链接字数 * 2
   —— 要求容器内至少有 2 个 <p>
3. 最后退路：body 文本 >= 500 字且有 >= 3 个 <p>
```

**为什么用平方根**：一篇文章 5000 字、侧栏广告 200 字，线性计分时文章稳赢；
但若正文只有 300 字、评论区 3000 字，线性计分会把评论区当正文。
平方根让"特别长"的边际收益递减。

**为什么噪声标签的文本不计入任何一项**：导航栏的字符数经常比正文还多。
把它算进 `textLen` 会让"包着导航的整个 wrapper"得高分，被误判成正文。
这一点有专门的测试（「噪声标签里的文字不给父容器加分」）。

## 3. 真实环境抓到的三个缺陷

### 缺陷 1（中）：`svg` 大小写 —— 噪声标签判断永远为假

| 项 | 内容 |
| --- | --- |
| **位置** | `NOISE_TAGS` 集合 |
| **错误** | 集合里写的是小写 `'svg'` |
| **后果** | HTML 里 `tagName` **永远是大写**，`NOISE_TAGS.has('SVG')` 恒为 false，SVG 内的文本（图标标题等）被当成正文加分 |
| **修复** | 改成 `'SVG'`，并加注释说明为什么必须大写 |
| **测试** | `reader-core.test.js` 的「svg 标签大小写必须与 tagName 一致」 |

这类缺陷的共性是"看起来对的字面量"。它是写代码时手滑，但**没有任何报错**，
只会让提取结果偶尔不准。

### 缺陷 2（高）：`scripting` 需要 host 权限，而 host 权限是 **optional** 的

| 项 | 内容 |
| --- | --- |
| **现象** | 真实 Chrome 里 `reader.toggle` 返回 `HANDLER_FAILED`，页面完全没反应 |
| **Chrome 的原话** | `Cannot access contents of the page. Extension manifest must request permission to access the respective host.` |
| **根因** | manifest 把 `https://*/*` 放在 `optional_host_permissions` 里（安装时不弹窗）。`executeScript` 需要该 host 已**被授予** |
| **为什么容易漏** | `chrome.permissions.getAll()` 在未打包扩展里**已经显示** `origins: ["https://*/*"]`，看起来像已授权；但 `executeScript` 仍会拒绝 |
| **修复** | 模块在 `install` 前先 `permissions.contains` 再（必要时）`permissions.request` |
| **细节** | **先查再请求**：`request` 每次都会弹确认框，已授权的站点不该反复弹 |

这个缺陷是本阶段最重要的产出。它说明：

> "manifest 里声明了权限" 与 "代码真的能用那个权限" 之间，
> 隔着一个**运行时授权**的步骤。而现成的骨架没覆盖这一步。

顺带纠正了一处语义错误：原本模块声明 `activeTab`，但 `activeTab` 只在
**用户点扩展图标**时授予，而阅读模式是从 popup 里对不同 tab 操作——
语义不对。改成 `hostHttps`。

### 缺陷 3（低）：测试工具的序列化范围不对

`serialize(doc)` 只遍历 `body`，而 `<style>` 装在 `head` 里。
于是"安装后应该不同"这条断言失败——**产品是对的，测试工具错了**。

修复：序列化 `doc.documentElement`（含 head）。

## 4. 两份实现与一致性测试

`chrome.scripting.executeScript({ func })` 会把函数**序列化后注入页面主世界**。
这意味着注入函数**不能引用任何外部变量**——所有 import 都不存在。

所以正文提取逻辑必须写两份：

| 位置 | 用途 |
| --- | --- |
| `lib/reader/core.js` | 单元测试、可读的参考实现 |
| `lib/modules/reader.js` 的 `readerToggle` | 真正注入页面的那份 |

**两份代码分叉的表现**是："单元测试用 core.js 全绿，真实浏览器却提不出正文"。

所以 `reader-module.test.js` 里有一组专门的一致性测试：用同一批页面
（标准文章页、语义标签页、只有导航、空页面、单段落容器）同时跑两份实现，
断言"提得出/提不出"的结论一致。

这不是优雅的做法，但它是 `executeScript` 的硬约束。
**与其假装能共享，不如把约束写明并加测试。**

## 6. 一个小小的稳健性改进

GUI 解锁是真实输入自动化，有时序抖动（egui 首帧布局、前台锁竞争）。
本轮遇到一次偶发失败，于是加了**一次**重试：

```js
let keyed = await waitFile(..., 15000);
if (!keyed) {
  // 只重试一次：连续两次失败说明是真的问题，不该用重试掩盖
  unlock = unlockGui(dirs, MASTER);
  keyed = await waitFile(..., 20000);
}
```

只重试一次是刻意的：无限重试会把"GUI 起不来"这种真问题变成偶发通过。

### 8.1 为什么自己写最小 DOM 替身而不装 jsdom

项目的依赖策略是「不引入未经审查的高风险依赖」。为了测 300 行 DOM 操作代码
引入 jsdom（几十个传递依赖、自己的 DOM 语义差异）不划算。

替身 292 行，**关键设计是：不认识的语法直接抛错**。

```js
throw new UnsupportedSelector(`替身不支持选择器 "${s}"。...`);
```

假实现最危险的失败方式是"宽松"——它接受任何输入，于是测试全绿，
真实浏览器却挂。阶段 2.9 的 `thirdParty` 缺陷就是这么漏掉的。

### 8.2 替身也确实抓到了东西

写这个替身的过程中，它立刻暴露了 `appendChild` 缺失
（注入函数用 `appendChild`，core.js 用 `append`——真实浏览器两者都有）。

## 10. 已知限制（如实）

| # | 项 | 说明 |
| --- | --- | --- |
| 1 | 提取算法是启发式 | 不保证对每个站点都对。安全阀是"提不出就什么都不做"，但"提成了错误的一小块"仍可能发生 |
| 2 | 克隆会丢事件监听 | 正文里的交互元素（折叠、懒加载图片）在阅读模式下失效。这是克隆方案的固有代价 |
| 3 | 不做图片懒加载处理 | 有些站点的图片是 `data-src`，克隆后不加载。需要时再加 |
| 4 | 首次使用需授权 | `optional_host_permissions` 意味着第一次点"进入阅读模式"会弹一次确认框。这是 Chrome 的设计，无法绕过 |
| 5 | 两份实现需人工保持一致 | 有测试守着结论一致，但细节（如打分权重）分叉时测试可能仍通过 |
| 6 | 只支持主 frame | `frameIds: [0]`。文章在 iframe 里的站点不支持 |
| 7 | 设置页还没有阅读模式的宽度/主题入口 | 配置项已就绪，UI 未做 |
| 8 | `svg` 之外的 SVG 子元素（circle/path）未特殊处理 | 它们没有文本，不影响打分；但若将来要做图片处理需要重新审视 |
