# 威胁模型

这份文档回答一个问题：**钥巢在什么情况下保护得了你，什么情况下保护不了。**

写它的目的不是免责，而是让你在放真实密码进来之前能做出判断。任何"全都防得住"的
安全声明都是假的——本地密码管理器有它无法逾越的边界。

---

## 1. 资产

| 资产 | 存放位置 | 敏感度 |
| --- | --- | --- |
| 主密码 | 用户记忆；运行期短暂存在于内存 | 最高 |
| KEK（主密码派生密钥） | 内存，函数作用域内，用完即清零 | 最高 |
| DEK（数据密钥） | 内存，受 `SecretKey` 保护，锁库即清零 | 最高 |
| 条目明文（密码、备注等） | 内存，解锁期间常驻 | 高 |
| `vault.dat` | 磁盘，密文 | 低（无主密码不可读） |
| 备份 `.bak.1..5` | 磁盘，密文 | 低（同上） |
| 明文导出 CSV/JSON | 用户指定的任意位置，**不加密** | 最高 |
| 剪贴板内容 | 系统剪贴板 | 高 |

---

## 2. 对手与场景

### A. 拿到库文件、没有主密码

**场景**：笔记本丢失、备份盘被盗、网盘账号被撞、`vault.dat` 被复制。

**结果**：只能得到密文。能否读出取决于主密码强度与 Argon2id 成本（64 MiB / t=3 / p=1）。

**残余风险**：弱主密码会被离线爆破。Argon2id 只提高每次尝试的成本，不消除风险。
12 位纯数字在这个成本下依然不安全。

### B. 拿到库文件、也知道主密码

**结果**：全部内容泄露。这是密码管理器的定义，无法缓解。

### C. 同机恶意程序（未提权）

**场景**：用户装了一个带后门的软件、浏览器扩展、被投毒的依赖。

**结果**：**防不住**。它可以读进程内存、记录键盘、截屏、读剪贴板。
`VirtualLock` 只挡住换页与休眠，不挡住同权限进程的内存读取。

**部分缓解**：自动锁定缩短了"已解锁窗口"的时间；剪贴板定时清除缩小了暴露面。

### D. 已提权的攻击者

**结果**：**完全防不住**。可以读内存、注入、改二进制、装驱动。任何本地软件在这种情况下都失守。

### E. 文件被篡改

**场景**：同步盘合并冲突、磁盘坏道、有人投放伪造的 `vault.dat`。

**结果**：**能防住**。AEAD 认证失败即拒绝解密；格式与算法配对校验会在解密之前就识别出结构异常。
不会"读出脏数据"，也不会 panic（有 600 段随机输入 + 截断 + 字节翻转的测试兜底）。

### F. 断电 / 崩溃 / 强杀

**结果**：**能防住主文件**。写入是「临时文件 → fsync → rename」，任一时刻磁盘上要么是旧版本、
要么是新版本，不存在半个文件。上一版还留在 `.bak.1`。

**残余风险**：rename 之后目录项未做单独的 fsync，极端断电下可能回退到上一版（数据不丢，丢的是最后一次修改）。

### G. 多实例并发

**场景**：开了两个窗口，各自改条目。

**结果**：**能防住**。单实例锁让第二个实例拿不到锁、在解锁前就停下。

### H. 外部程序改了库文件

**结果**：**能防住**。保存前比对磁盘指纹（长度 + `updatedAt`），不一致就拒绝写入并提示，
而不是把对方的改动整体覆盖掉。

**残余风险**：不比对 mtime（杀软、备份工具都会改 mtime，用它判等会大面积误报），
所以"内容逐字节相同但被重写"检测不到——那也不构成损失。

### I. 回滚攻击

**场景**：攻击者把 `vault.dat` 换成你三天前的备份。

**结果**：**防不住**。密文是自洽的，程序无法区分"这是最新的"和"这是旧的"。
需要防回滚的话得引入单调计数器或可信时间源，那与"纯本地、无状态"的设计冲突。

**造成的后果**：最近三天的修改消失。这也是备份策略的另一面：`.bak.1..5` 本身就是可被用来回滚的素材。

### J. 换主密码之后

**结果**：**新文件**由新主密码保护；**旧备份仍然由旧主密码保护**。

这是必须说清楚的一条：`change_master` 只重新包裹 DEK，不回写 `.bak.*`。
如果你怀疑主密码泄露，改密码之后**还要销毁旧备份**，否则攻击者拿到 `.bak.3` 照样能开。

### K. 明文导出之后

**结果**：导出的 CSV / JSON 是**任何程序都能读的文本**。程序只能在你点导出时提醒一次，
文件落盘之后的一切（被同步、被索引、被恶意软件扫走）都超出它的能力范围。

**建议**：导出 → 立刻导入目标软件 → 删除文件。

### L. 屏幕被拍 / 被人盯着 / 被胁迫

**结果**：**防不住**。任何软件都防不住。

### M. 侧信道

**结果**：主密码**从不被直接比较**，所以不存在「比较耗时泄漏前缀长度」这回事。

具体分两条路径，机制不同但都是常量时间的：

| 路径 | 怎么判定密码对错 |
| --- | --- |
| **解锁**（`unlock`） | 派生 KEK → AEAD 解包 DEK。密码错则 **tag 校验失败**，解不开 |
| **升级格式**（`upgrade_to_v2/v3`） | 派生 KEK → 与当前密钥 `ct_eq` 比较（`subtle` 的常量时间实现） |

解锁路径的常量时间性来自两处：**Argon2id 派生耗时固定**，
以及 **AEAD 的 tag 校验本身是常量时间的**（RustCrypto 内部用 `subtle`）。

`subtle` 在本项目里的**直接**用途是密钥比较（`keymem.rs` 的 `ct_eq`），
用于解包后的 DEK / KEK 比对，以及升级路径的密码校验——
不是主密码字符串的比较。

加密实现本身的安全性依赖 RustCrypto 的正确性——
本项目没有对底层原语做独立验证。

## 3. 一张表

| 场景 | 结论 |
| --- | --- |
| 库文件被拷走 | ✅ 只有密文 |
| 库文件被篡改 | ✅ 认证失败，拒绝解密 |
| 断电 / 崩溃 | ✅ 原子写入 + 备份 |
| 多开窗口 | ✅ 单实例锁 |
| 外部改动 | ✅ 指纹比对后拒绝保存 |
| 回滚到旧文件 | ❌ 无法检测 |
| 换密码后旧备份 | ❌ 仍由旧密码保护 |
| 同机恶意程序 | ❌ 防不住 |
| 提权攻击者 | ❌ 防不住 |
| 弱主密码离线爆破 | ⚠️ 只提高成本 |
| 明文导出后的文件 | ❌ 完全在程序之外 |
| 屏幕被拍 / 被胁迫 | ❌ 防不住 |

## 4. 缓解措施的实际边界

| 措施 | 挡住了什么 | 没挡住什么 |
| --- | --- | --- |
| `VirtualLock` | 换页、休眠文件、崩溃转储 | 同权限进程读内存 |
| `Zeroize` | 结构体 drop 后的内存 | `String` 扩容留下的旧堆片段 |
| 剪贴板 TTL | 复制后长时间残留 | 期间被别的程序读走 |
| 不进剪贴板历史 | Win+V 历史、云同步 | 剪贴板监视器 |
| 自动锁定 | 离开座位后的窗口期 | 期间的一切活动 |
| 单实例锁 | 并发覆盖 | 用户自己手动复制文件 |
| 5 代备份 | 单次损坏 | 回滚攻击（备份本身即素材） |

---

## 5. 如果你要更高的安全性

本项目的形态决定了它的上限。需要更强保证时：

- 用**硬件密钥 / Passkey** 作为第二因子（本项目尚未支持，Roadmap P2）
- 把库放在**全盘加密 + 受控物理环境**的机器上
- 主密码用 **4 个以上不相干的词**（≈ 50 bit 起），而不是 12 位随机字符
- 定期把**加密备份**拷到离线介质，并删除过期的 `.bak.*`
